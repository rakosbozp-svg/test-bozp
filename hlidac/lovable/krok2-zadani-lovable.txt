## Roles
There are exactly three roles:
1. **Hlavní správce (admin)** – sees and edits everything, manages users. ONLY these e-mail addresses can ever be admin: `rakos@zpsv.cz` and `rakos.bozp@gmail.com`. Store them in a table `app_admin_emails(email text primary key)` seeded with these two. A database trigger/check must make it impossible to give the 'admin' role to any user whose profile e-mail is not in that table, and anyone who registers with one of these e-mails is automatically approved and gets 'admin'.
2. **Správce firmy (role 'firma')** – sees and edits only the data of the companies assigned to them (all plants of those companies).
3. **Správce závodu (role 'zavod')** – sees and edits only the data of the plants (závody) assigned to them.

Extend the `app_role` enum with 'firma' and 'zavod' (keep 'user' only for backward compatibility, do not assign it anymore).
New table `user_scopes`: id uuid pk, user_id uuid, company_id uuid null, plant_id uuid null, created_at; check exactly one of company_id / plant_id is set; unique (user_id, company_id, plant_id). Only admins can read all / write; a user can read their own rows.
